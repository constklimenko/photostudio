# D1.1 — План минимального эксперимента для D1.2–D1.3

**Дата:** 2026-09-20
**Контекст:** план практической проверки прототипов image tracking на подэтапах
D1.2 (распознавание и удержание) и D1.3 (видео поверх фото). Продолжает
`docs/AR-TECHNOLOGY-RESEARCH.md` (shortlist D1.1) и `docs/AR-TARGET-REQUIREMENTS.md`
(`[ЭКСП]`-параметры). Документ — инструкция, а не протокол: сам эксперимент не
выполнялся, решения (выбор SDK) им не принимаются.

**Формат инструкции:** подготовить → протестировать → измерить → принять результат.

---

## 0. Минимум фактов, на которых строится план

- iOS Safari не имеет WebXR → на iPhone работают только движки с собственным CV:
  MindAR, 8th Wall, AR.js (`AR-TECHNOLOGY-RESEARCH.md` §1.4, §2).
- Первые 1–2 технологии на прототип — **MindAR (v1.2.5)** и
  **8th Wall Open Source (MIT-фреймворк, Image Targets, без SLAM)**: оба MIT,
  self-host, без облачной зависимости, покрывают iOS Safari. AR.js — B-план,
  запускать только если обе первые технологии провалят критерий iOS
  (`AR-TECHNOLOGY-RESEARCH.md` §4).
- Типовой кадр Фотосказки (студийный портрет анфас, однотонный фон, глянцевая
  печать) — худший класс target-изображений; вопрос «работает ли как есть»
  решается только экспериментом (`AR-TARGET-REQUIREMENTS.md` §13–§14).
- Численные пороги (размер, дистанция, угол, освещённость) документацией не
  заданы → пороги принимаем экспериментально по ходу прогона
  (`AR-TARGET-REQUIREMENTS.md` §15).

## 1. Что подготовить

### 1.1 Технологии (две, равноприоритетно)

| Технология | Сборка target | Тестовая страница |
|---|---|---|
| **MindAR** | браузерный Image Targets Compiler → `targets.mind` (оценить число/распределение feature-точек до печати) | статичная стр. с `mindar-image-target`; D1.2 — заглушка-контент, D1.3 — `<video>` (`muted` + `playsInline`) |
| **8th Wall Open Source** | `npx @8thwall/image-target-cli` → метаданные target в проект | статичная стр. на MIT-движке (engine + Image Targets) |

Требования к обеим: доступ по **HTTPS** (secure context, без него камера
недоступна), отдача с одного домена без CORS-проблем, для iPhone — реальный
домен с HTTPS (не `localhost`).

### 1.2 Фотографии (2 обязательные + 1 опциональная)

1. **Контрольная «хорошая»** — богатая деталями сцена (группа на улице, коллаж,
   интерьер). Проверяет, что пайплайн технологии вообще рабочий.
2. **Типовой студийный портрет** — одиночный, анфас, однотонный фон (главный
   продакшн-вопрос: работает ли «как есть»).
3. _[опционально]_ **Групповой классный снимок** (ряды лиц) — класс контента
   с риском повторов/симметрии.

Исходники: оригинал с максимальным разрешением (не превью), сторона ≥1000 px,
RGB, без пережатия (`AR-TARGET-REQUIREMENTS.md` §8.1). Печать и компиляция target
идут **из одного и того же файла** — геометрия должна совпадать (§9).

### 1.3 Печать (5 отпечатков минимум)

- 2 «хороших» фото × **матовая** печать в размерах **10×15 см** и **20×30 см**
  (страница альбома): итого 4.
- **Глянцевая 10×15 см** портрета — только для проверки бликов: итого 5.

Без полей/рамок/паспарту, жёсткая основа (плотный картон/фоам 3–5 мм), печать
«1:1 по кропу» тем же файлом.

### 1.4 Устройства (2)

- средний **Android** (Chrome, актуальная версия);
- **iPhone** (iOS Safari, последние 2–3 поколения).

Перед прогоном записать: модель, версию ОС/браузера, разрешение камеры.

### 1.5 Условия освещения (3 режима)

1. **Искусственный ровный свет** — комнатный, без направленных бликов
   (эталон для критерия D1.2 «нормальное освещение»).
2. **Дневной свет** — рассеянный у окна / на улице (критерий D1.3).
3. **Блик** — направленный источник, отражающийся в глянцевом отпечатке
   (robustness-проверка).

Люксометр (приложение на телефоне) — опционально, фиксировать при наличии.

### 1.6 Видео (для D1.3)

Короткий тестовый ролик **10–20 сек**: H.264 MP4 + WebM (для надёжного
`muted`-автозапуска на iOS), `muted` + `playsInline`.

## 2. Что протестировать (минимальная матрица)

### 2.1 Матрица «комбо»

На каждую комбинацию **технология × телефон** прогоняется основной блок:

| Фото | Печать / размер | Свет |
|---|---|---|
| Контрольная | мат 10×15, мат 20×30 | искусственный, дневной |
| Студийный портрет | мат 10×15, мат 20×30 | искусственный, дневной |
| Студийный портрет | **глянец** 10×15 | искусственный, **блик** |
| _Групповой снимок_ | _мат 10×15_ | _искусственный_ |

Итого: 2 технологии × 2 телефона × (до 5 отпечаток-свет-комбо) ≈ **≤40 проверок**
основного блока, по N=5 попыток на комбо.

### 2.2 Сценарии tracking (на каждое комбо)

1. **Распознавание** — наведение на фото, ожидание появления оверлея при
   рабочей дистанции «фото в руках» (25–40 см).
2. **Удержание** — сфокусированный target в кадре **≥5 сек** (неподвижно и при
   медленном движении камеры).
3. **Потеря/повторное распознавание** — увод камеры в сторону, возврат; время
   до повторного распознавания.
4. **Видео (D1.3)** — запуск видео при `targetFound`, пауза/возврат при
   `targetLost`, автозапуск без жеста, включение звука тапом (iOS).
5. _[опционально, быстрый проход]_ наклон 0°/≈30° и дальняя дистанция ≈1 м на
   отпечатке 20×30.

## 3. Что измерить (протокольная строка на каждую попытку)

| Метрика | Единица | Когда важно |
|---|---|---|
| Технология, телефон, фото, печать, размер, свет | — | всегда (столбцы комбо) |
| Распознан / не распознан | да/нет | всегда |
| Время до распознавания | сек | первые 5 сек = ожидаемый UX |
| Удержание ≥5 сек | да/нет + длительность, сек | критерий D1.2 |
| Успешных из N=5 попыток | % | итого по комбо |
| Повторное распознавание после потери | сек / «не восстановилось» | стабильность |
| Видео: запуск при found, muted-автостарт, звук по тапу | да/нет | D1.3 |
| Позиционирование оверлея относительно фото | «совпадает / смещено» | качество контента |
| Замечания (фризы, джиттер, нагрев) | текст | поведение на среднем Android |

## 4. Как принять результат

### Критерии готовности (из roadmap, без изменений)

- **D1.2 готов:** минимум на двух устройствах (Android + iOS) печатное фото
  распознаётся и удерживается **не менее нескольких секунд более чем в 50%**
  попыток при нормальном освещении.
- **D1.3 готов:** хотя бы на одной паре «SDK × телефон» **видео** стабильно
  запускается и отслеживается при **искусственном и дневном** освещении;
  зафиксированы предельные параметры качества печати (влияние глянца, граница
  размера 10×15 vs 20×30, максимальная дистанция/наклон).

### Решение о продолжении (вход для D1.4/D1.5, не само решение)

| Исход прогона | Действие |
|---|---|
| MindAR **или** 8th Wall проходит оба критерия | фиксируем лидера/отстающего, данных хватает для D1.4 и D1.5 |
| Обе проходят | сравниваем по скорости распознавания, UX и простоте сборки — вход для выбора на D1.5 |
| Ни одна не проходит | подключаем AR.js (B-план), повторяем минимальный блок; если провал у всех — на D1.5 пересматриваем в пользу коммерческого/гибридного варианта |

Результаты прогона оформляются как отчёт D1.2/D1.3: по одному абзацу на каждую
метрику критериев + сводная таблица комбо.

## 5. Что не входит в этот прогон (отложено)

- Полная браузерная матрица (Firefox, Edge, webview) и решётка дистанций
  с шагом — это D1.9.
- Множественные одновременные targets, тёплый/холодный старт ссылки, статистика
  и аналитика — D1.6.
- Сравнительная нагрузка видео (битрейт/длительность, CDN) — D1.7.

Здесь цель — только ответить на критерии D1.2/D1.3 минимальным числом проверок.
