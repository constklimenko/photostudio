- ОС: **Ubuntu 20.04.6 LTS (focal)**. Стандартная поддержка закончилась 31.05.2025.
- Ubuntu Pro / ESM **не подключён** → обновления безопасности не приходят.
- Ядро: запущено `5.4.0-174` (март 2024), установлено `5.4.0-216` (апрель 2025) — нужен ребут.
- `unattended-upgrades` отсутствует.
- Docker 28.1.1, Compose 2.35.1, containerd 1.7.27 — репозиторий для focal заморожен.
- Хостовые сервисы: `exim4` (только localhost), `pure-ftpd` (порт 21), `fail2ban`, `ufw`.
- Хостовый PHP 7.4 (PPA `ondrej/php`) — EOL с 2022, нигде не слушает.
- Приложение изолировано в Docker (Debian 13, PHP 8.4) — обновление ОС влияет в основном на Docker, certbot и хостовые пакеты.

## Шаг 0. Немедленно: Ubuntu Pro (ESM)

Бесплатно до 5 машин, даёт security-обновления для 20.04 до апреля 2030.

1. Получить токен на https://ubuntu.com/pro (нужен аккаунт Ubuntu One).
2. На сервере:

   ```bash
   pro attach <token>
   pro enable esm-infra esm-apps
   apt update
   apt upgrade -y
   ```

3. Перезагрузиться в актуальное ядро (короткий простой):

   ```bash
   reboot
   ```

4. Проверить: `pro status`, `uname -r`, `apt list --upgradable`.
5. Включить автообновления безопасности:

   ```bash
   apt install unattended-upgrades
   dpkg-reconfigure -plow unattended-upgrades
   ```

Это покупает время (до 2030) и снимает главный риск, пока готовится миграция.

## Шаг 1. Выбор пути

### Вариант A (рекомендуемый): новый сервер с Ubuntu 24.04 LTS

Чистая установка, предсказуемый результат, простой откат — старый сервер остаётся рабочим.

1. Создать VPS с Ubuntu 24.04 LTS, тот же/больший диск (сейчас занято ~14 ГБ из 20 ГБ).
2. Установить Docker Engine и compose-плагин из официального репозитория.
3. Перенести:
   - `/var/www/fotoskazka` (код, `docker-compose.yml`), **без** `storage/app/image-cache`;
   - `.env` (секреты) — безопасным каналом;
   - `storage/app/public` (~4.6 ГБ медиа) и `storage/app/backups`;
   - дамп БД (см. `docs/OPS-MYSQL-8.4-UPGRADE.md`);
   - `/etc/letsencrypt`, скрипты nginx, настройки UFW/fail2ban.
4. Поднять стек, импортировать БД, проверить сайт по IP/hosts.
5. Переключить origin в CDN (turboflare) на новый IP; проверить HTTPS и почту.
6. Оставить старый сервер выключенным 1–2 недели как откат.

### Вариант B: in-place 20.04 → 22.04 → 24.04

Дешевле по ресурсам, но выше риск и дольше простой.

1. Снапшот сервера у провайдера + полный бэкап БД и медиа вне сервера.
2. Подготовка:
   - удалить PPA `ondrej/php` и пакеты PHP 7.4 (не используются);
   - остановить `pure-ftpd`, если FTP не нужен;
   - освободить 5+ ГБ на диске;
   - `apt update && apt upgrade`, ребут.
3. `do-release-upgrade` до 22.04, ребут, проверка стека.
4. `do-release-upgrade` до 24.04, ребут, проверка стека.
5. Переустановить/обновить Docker при необходимости, проверить `docker compose up -d`.
6. Проверки: сайт, админка, заявка с почтой, очередь, сертификаты, бэкапы.
