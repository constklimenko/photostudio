# S3-хранилище как альтернатива Яндекс.Диску

## Назначение

Оригиналы изображений можно хранить не локально и не на Яндекс.Диске, а в
S3-совместимом бакете. Диск выбирается для **новых** загрузок; у каждой
записи `media` уже есть поле `disk`, поэтому старые файлы продолжают
работать со своих дисков.

Поддерживаются диски:

| `MEDIA_DISK` | Хранилище |
|---|---|
| `public` | локальный `storage/app/public` (по умолчанию) |
| `s3` | S3-бакет |
| `yandex_disk` | Яндекс.Диск |

Thumbnails и кэш производных изображений всегда остаются локальными
(`thumbnails`, `image_cache`) — на S3 уходят только оригиналы.

## Параметры Reg.ru Cloud

- S3 API endpoint: `https://s3.regru.cloud`
- Бакет: `fotoskazka`
- Публичный доступ: только чтение (bucket policy)
- Публичные ссылки:
  - path-style: `https://s3.regru.cloud/fotoskazka/<key>`
  - virtual-hosted: `https://fotoskazka.s3.regru.cloud/<key>`
- Хост `fotoskazka.website.regru.cloud` для объектов этого бакета
  отдаёт 404 — использовать его как `AWS_URL` не нужно.

## Настройка `.env`

```dotenv
MEDIA_DISK=s3

AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
AWS_DEFAULT_REGION=us-east-1
AWS_BUCKET=fotoskazka
AWS_ENDPOINT=https://s3.regru.cloud
AWS_URL=https://s3.regru.cloud/fotoskazka
AWS_USE_PATH_STYLE_ENDPOINT=true
```

Ключи доступа хранятся только в `.env` (не в БД и не в репозитории).
При компрометации ключ отзывается в панели Reg.ru Cloud.

## Проверка подключения

```bash
php artisan config:clear
php artisan media:test-storage --disk=s3
```

Команда выполняет полный цикл: создать папку → записать файл → прочитать →
сверить содержимое → удалить. Успешный результат:

```
Хранилище [s3] работает корректно.
```

Проверка публичного доступа к загруженному объекту:

```bash
curl -I https://s3.regru.cloud/fotoskazka/<путь>/<файл>
```

Ожидается `200` и корректный `Content-Type`.

## Включение для новых загрузок

1. Заполнить ключи в `.env`.
2. Поставить `MEDIA_DISK=s3`.
3. Пересобрать конфиг и перезапустить контейнеры (в php.ini
   `opcache.validate_timestamps=0`):

   ```bash
   php artisan config:cache
   docker compose restart app queue
   ```

4. Загрузить тестовый альбом в админке и проверить:
   - запись в `media` имеет `disk = s3`;
   - оригинал открывается по `/media/{id}/original`;
   - миниатюра и lightbox работают (они локальные);
   - публичная ссылка `https://s3.regru.cloud/fotoskazka/...` отвечает 200.

## Важно: публичный бакет и приватные галереи

Бакет открыт на чтение всем. В нём **нельзя** хранить оригиналы
клиентских/проектных альбомов (`album.type = client|project`): прямой URL
объекта обойдёт проверку доступа `MediaAccessService`. Для приватных
материалов нужен отдельный приватный бакет (закрытый policy + временные
подписанные ссылки) либо локальный приватный диск.

Сейчас на проде приватных альбомов нет, поэтому использование S3 для
публичного портфолио безопасно. Перед запуском личного кабинета (C2)
вопрос приватного хранилища нужно решить отдельно.

## Существующие Media

Для переноса уже загруженных оригиналов на S3 есть команда:

```bash
php artisan media:migrate-to-s3 --dry-run
php artisan media:migrate-to-s3 --limit=50
```

Порядок для каждой записи: upload → проверка размера и sha256 → обновление
`media.disk` → удаление исходного оригинала. Команда идемпотентна:
повторный запуск пропускает записи, уже находящиеся на S3, и переиспользует
совпадающий по содержимому файл. Полезные опции:

- `--dry-run` — показать план без изменений;
- `--limit=N` — обработать не больше N записей за запуск;
- `--media-id=ID` — мигрировать только одну запись;
- `--keep-source` — не удалять исходный оригинал после проверки (по
  умолчанию источник удаляется, как в миграции на Яндекс.Диск).

Thumbnails и кэш производных при миграции не переносятся: они остаются
локальными. Кэш display/lightbox для изменённого `disk` создаётся заново
при первом запросе.

## Видео

Загруженные видео хранятся в отдельной таблице `videos` и используют диск
`VIDEO_DISK` (по умолчанию `public`). Это сделано специально, чтобы
переключение `MEDIA_DISK` на S3 не ломало существующие видео. Видео можно
перенести на S3 отдельно: скопировать каталог `videos/` в бакет и поставить
`VIDEO_DISK=s3`; `VideoController` умеет отдавать файлы с S3 (без
X-Accel-Redirect, через поток).

## Отдача файлов

`MediaController@original` читает оригинал с диска записи и отдаёт через
PHP после проверки доступа — для S3 это работает без изменений. Если
понадобится разгрузить сервер, для публичных Media можно добавить redirect
на публичный URL бакета (после проверки `MediaAccessService::isPublic`).
