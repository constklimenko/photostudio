# Этап 3.5. Улучшение работы с заявками

## Цель

Превратить сущность **Заявка (Inquiry)** из простого сообщения с сайта в начальную точку жизненного цикла клиента.

После выполнения задачи администратор сможет:

* видеть полную историю заявки;
* получать уведомления;
* менять статус заявки;
* создавать проект непосредственно из заявки;
* быстро переходить между заявкой и созданным проектом.

Проект должен стать основой для дальнейшего развития CRM и клиентских кабинетов.

---

# Этап 1. Изменение структуры БД

Добавить в таблицу `inquiries`:

```php
project_id BIGINT NULL
```

Foreign key:

```
project_id -> projects.id
ON DELETE SET NULL
```

Индекс:

```
INDEX(project_id)
```

---

## Модели

### Inquiry

Добавить отношения

```php
project(): BelongsTo
```

### Project

Добавить

```php
inquiry(): HasOne
```

(один проект создаётся только из одной заявки)

---

# Этап 2. Создание проекта из заявки

На странице просмотра/редактирования заявки Filament добавить Action:

```
Создать проект
```

Кнопка отображается только если

```
project_id == null
```

---

При нажатии:

1. открывается небольшая форма;

Поля:

* название проекта
* тип проекта
* менеджер
* клиент (если выбран пользователь)
* дата съёмки (по умолчанию из заявки)

---

После подтверждения:

создать запись Project

автоматически заполнить:

```
title

type

client_id

manager_id

shooting_date

status = draft
```

при создании проекта  автоматически копировать в него контактные данные из заявки (имя, телефон, email) и предусмотреть соответствующие поля в проекте (contact_name, contact_phone, contact_email). 

после создания

```
inquiries.project_id
```

заполняется автоматически.

Использовать отдельный Action-класс

```
CreateProjectFromInquiry
```

Вся логика создания должна находиться только там.

---

# Этап 3. Навигация между сущностями

После создания проекта:

в карточке заявки появляется блок

```
Проект

Название проекта

Статус

Тип

Открыть проект →
```

Ссылка ведёт сразу на

```
/admin/projects/{id}/edit
```

---

В карточке проекта вывести обратную информацию

```
Источник

Заявка №15

Имя

Телефон

Email

Открыть заявку →
```

---

Таким образом пользователь сможет переходить в обе стороны.

# Этап 5. Email-уведомления

После поступления новой заявки автоматически отправлять письмо администратору.

Использовать стандартный Laravel Notification/Mail.

Письмо должно содержать:

* имя
* телефон
* email
* услугу
* комментарий
* дату съёмки

и кнопку

```
Открыть заявку
```

---

После изменения статуса заявки на

```
completed
```

уведомления отправлять не требуется.

---

# Этап 6. Telegram

Добавить сервис уведомлений Telegram.

Конфигурация через .env

```
TELEGRAM_BOT_TOKEN=

TELEGRAM_CHAT_ID=
```

Создать сервис

```
TelegramNotifier
```

или аналогичный.

При создании заявки отправлять сообщение.

Пример:

```
Новая заявка

Иван Петров

Телефон

+7 ...

Услуга

Выпускной альбом

Дата

15.09.2026

Комментарий

...

Открыть заявку
```

Если Telegram недоступен,

создание заявки не должно завершаться ошибкой.

Ошибку необходимо логировать.

# Этап 7. Архитектура

Не размещать бизнес-логику внутри Filament Pages.

Использовать:

```
app/Actions/

    Inquiry/
        CreateProjectFromInquiry.php

    Notification/
        SendInquiryEmail.php
        SendInquiryTelegram.php
```

Filament должен только вызывать соответствующие Action.

# Этап 8. Тесты

Добавить Feature и Unit тесты.

Проверить:

* создание проекта из заявки;
* повторное создание невозможно;
* после создания появляется связь;
* проект содержит корректные данные;
* переход между проектом и заявкой работает;
* email отправляется;
* Telegram вызывается;
* ошибка Telegram не ломает создание заявки.
