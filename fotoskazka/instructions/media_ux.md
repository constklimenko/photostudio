# Фотосказка — Этап улучшения Media Library и UX админки

## Контекст

Текущая реализация Filament Resource для Media представляет собой прямое отображение структуры таблицы `media`.

Это технически корректно, но неудобно для реального пользователя (фотографа).

Необходимо перейти от CRUD-интерфейса базы данных к рабочему интерфейсу управления фотографиями и галереями.

---

# Этап 1. Улучшение модели данных

## 1.1 Альбомы без проекта

### Проблема

Сейчас каждый альбом обязан принадлежать проекту.

Это не позволяет использовать альбомы для:

* главной страницы;
* портфолио;
* услуг;
* произвольных галерей сайта.

### Требуется

Сделать связь с проектом необязательной.

### Изменения БД

Таблица:

```sql
albums
```

Поле:

```sql
project_id
```

изменить на:

```sql
project_id BIGINT NULL
```

### Миграция

Создать отдельную миграцию изменения структуры.

---

## 1.2 Добавить тип альбома

### Проблема

Сейчас невозможно отличить клиентский альбом от галереи портфолио.

### Требуется

Добавить поле:

```sql
type
```

Возможные значения:

```text
portfolio
project
homepage
service
client
```

### Назначение

portfolio

* галереи портфолио

project

* альбомы съёмок

homepage

* слайдеры и блоки главной страницы

service

* галереи услуг

client

* клиентские галереи

### Значение по умолчанию

```text
portfolio
```

# Этап 2. Рефакторинг Media

## 2.1 Скрыть технические поля

### Проблема

Пользователь не должен знать внутреннюю структуру хранения файлов.

### Удалить из формы создания и редактирования

```text
Disk
Thumbnail Path
Mime Type
Width
Height
File Size
```

Эти поля должны заполняться автоматически.

### Разрешить редактирование только

```text
Title
Alt Text
Collection
```

---

## 2.2 Автоматическое заполнение метаданных

После загрузки файла автоматически определять:

```text
mime_type
width
height
file_size
```

### Источник данных

Laravel Storage + PHP image functions.

---

## 2.3 Автоматическая генерация превью

После загрузки изображения:

1. создать превью;
2. сохранить путь в thumbnail_path;
3. сохранить размеры превью.

Пользователь не должен указывать thumbnail_path вручную.

# Этап 3. Массовая загрузка фотографий

## Цель

Основной сценарий работы фотографа:

* выбрать 20–500 фотографий;
* загрузить их одной операцией;
* автоматически получить альбом.

---

## 3.1 Создать отдельную страницу загрузки

Не использовать стандартный CRUD Media Create.

Создать отдельную страницу:

```text
Контент → Загрузка фотографий
```

---

## 3.2 Интерфейс

На странице разместить:

### Поле загрузки

Поддержка:

* drag & drop
* множественный выбор файлов

### Поля альбома

```text
Название альбома
Описание
Тип альбома
Обложка (опционально)
```

### Для типа project

Показывать дополнительное поле:

```text
Проект
```

---

## 3.3 Логика загрузки

После нажатия:

```text
Создать альбом
```

система должна:

### Шаг 1

Создать запись Album.

### Шаг 2

Для каждого файла:

создать запись Media.

### Шаг 3

Автоматически:

* определить размеры;
* определить mime-type;
* определить размер файла;
* создать превью.

### Шаг 4

Создать запись Photo.

### Шаг 5

Связать Photo с Album.
