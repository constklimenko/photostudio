# Задача: Переработка системы ролей, доступа и подготовка пользовательского кабинета

## Цель

Разделить административную панель и пользовательскую часть сайта.

Filament используется **исключительно как административная панель**.

Все остальные пользователи работают через отдельный личный кабинет, который будет построен на Blade.

---

# 1. Ограничение доступа к Filament

Изменить логику доступа к панели `/admin`.

## Требования

Доступ разрешён только пользователям:

* имеющим роль `admin`;
* имеющим статус `active`.

Наличие любых других ролей не должно влиять на доступ.

Примеры:

| Роли пользователя    | Доступ в /admin |
| -------------------- | --------------- |
| admin                | ✅               |
| admin + photographer | ✅               |
| admin + client       | ✅               |
| photographer         | ❌               |
| client               | ❌               |
| parent               | ❌               |
| class_manager        | ❌               |

Необходимо изменить `User::canAccessPanel()`.

---

# 2. Методы проверки ролей

Добавить в модель `User` удобные методы.

Обязательные:

```php
isAdmin(): bool

hasRole(string $slug): bool

hasAnyRole(array $roles): bool

hasAllRoles(array $roles): bool
```

Во всём проекте использовать именно эти методы вместо ручных запросов к pivot-таблице.

---

# 3. Команда создания администратора

Команда

```bash
php artisan make:filament-user
```

должна автоматически:

1. создать пользователя;
2. назначить ему роль `admin`.

Если роль отсутствует в базе:

* найти её по `slug`;
* при необходимости создать автоматически.

После выполнения команды пользователь всегда должен иметь возможность войти в `/admin`.

---

# 4. Системные роли

Добавить в таблицу `roles` поле

```text
is_system BOOLEAN DEFAULT TRUE
```

Начальные роли должны иметь

```text
is_system = true
```

Список:

* admin
* photographer
* client
* parent
* class_manager

---

# 5. Защита системных ролей

В Filament необходимо запретить:

* удаление системных ролей;
* изменение поля `slug` у системных ролей.

При этом допускается изменение отображаемого названия (`name`).

Пользовательские роли (`is_system = false`) должны полностью редактироваться.

---

# 6. Пользовательские роли

Администратор должен иметь возможность создавать собственные роли.

Например:

* retoucher
* assistant
* manager
* designer

Количество ролей у пользователя не ограничивается.

Many-to-many связь остаётся без изменений.

---

# 7. Личный кабинет

Подготовить каркас пользовательского кабинета.

Использовать:

* Blade;
* обычные Laravel Controller;
* обычные маршруты.

Не использовать Filament.

Маршрут:

```
/cabinet
```

Пока достаточно создать:

```
CabinetController

index()

resources/views/cabinet/index.blade.php
```

Страница должна быть защищена middleware `auth`.

Временно вывести простое приветствие.

Например:

```
Личный кабинет

Здравствуйте, Иван Иванов
```

Функциональность кабинета будет развиваться позднее.

# Ожидаемый результат

После выполнения задачи система должна иметь следующую архитектуру:

* Filament доступен только администраторам;
* команда `make:filament-user` всегда создаёт администратора;
* пользователь может иметь неограниченное количество ролей;
* системные роли защищены от удаления и изменения;
* подготовлен каркас личного кабинета `/cabinet`;
* шапка сайта отображает ссылки в зависимости от роли пользователя;
* все изменения покрыты тестами.
