# Задача: вынести контент публичных страниц в CMS

## Цель

Сейчас публичные страницы содержат большое количество захардкоженного текста в Blade-шаблонах.

Необходимо сделать так, чтобы администратор мог изменять основные тексты сайта через Filament без изменения кода.

Важно сохранить существующую архитектуру проекта: контроллеры получают данные из моделей, Blade остаётся максимально "тупым".

---

# Общая идея

Использовать существующую таблицу `pages` как источник контента для:

* страницы Услуги;
* страницы Портфолио;
* страницы Блог;
* Главной страницы (для заголовков её блоков).

При этом **таблица pages не должна становиться конструктором страниц**.

Она отвечает только за:

* заголовки;
* подзаголовки;
* большие описания;
* SEO;
* отображение блока на главной.

Контент блоков продолжает загружаться из соответствующих моделей:

* Services;
* Albums;
* Posts;
* Testimonials.

---

# Этап 1. Расширить таблицу pages

Добавить миграцию.

Новые поля:

```php
subtitle TEXT NULL

home_title VARCHAR(255) NULL

home_subtitle TEXT NULL

show_on_home BOOLEAN DEFAULT FALSE

home_sort_order INT DEFAULT 0

menu_title VARCHAR(255) NULL
```

Существующие поля оставить без изменений.

Использовать существующие:

```
title

content

seo_title

seo_description

cover_media_id

slug
```

---

# Назначение полей

## title

Заголовок страницы.

Например

```
Наши услуги
```

---

## subtitle

Подзаголовок страницы.

---

## content

Большое описание страницы.

Используется только там, где необходимо.

---

## home_title

Заголовок блока на главной.

Например

```
Фотосессии
```

---

## home_subtitle

Подзаголовок блока на главной.

---

## show_on_home

Показывать ли блок на главной.

---

## home_sort_order

Порядок блока на главной.

Пока использовать только при выборке.

Даже если шаблон ещё не умеет менять порядок, поле должно быть готово.

---

## menu_title

Название пункта меню.

Если пусто —

использовать title.

---

# Этап 2. Сидер страниц

Создать сидер.

Добавить записи:

```
home
services
portfolio
blog
```

Slug должны быть фиксированными.

Пример:

```
home

services

portfolio

blog
```

Заполнить разумными начальными значениями.

Например

```
title

subtitle

home_title

home_subtitle

menu_title
```

---

# Этап 3. Улучшить Filament Resource

Форму Pages сделать более удобной.

Разделить поля на секции.

## Основная информация

```
title

menu_title

slug
```

---

## Заголовок страницы

```
subtitle

cover

content
```

---

## Главная страница

```
show_on_home

home_sort_order

home_title

home_subtitle
```

Если

```
show_on_home = false
```

то остальные поля блока можно скрывать.

---

## SEO

Оставить существующие поля.

---

# Этап 4. Создать сервис получения страниц

Создать сервис.

Например

```
PageContentService
```

или аналогичный.

Он должен получать страницу по slug.

Например

```php
$page = $pageContent->get('services');
```

В сервисе желательно использовать кэш.

Интерфейс должен быть максимально простым.

---

# Этап 5. Обновить контроллеры

Переделать:

```
HomeController

ServiceController

PortfolioController

BlogController
```

Чтобы они передавали страницу в Blade.

Например

```
$page
```

---

# Этап 6. Переделать Blade

Убрать захардкоженные заголовки.

Использовать данные страницы.

Например

Вместо

```
Наши услуги
```

использовать

```
$page->title
```

Вместо

```
Выберите подходящий формат съёмки
```

использовать

```
$page->subtitle
```

---

На главной

для каждого блока использовать

```
home_title

home_subtitle
```

если они заполнены.

Контент блока (услуги, статьи, отзывы, альбомы) продолжает загружаться из соответствующих моделей.

---

# Этап 7. Меню сайта

Компонент Header должен получать список опубликованных страниц.

Название пункта меню:

```
menu_title
```

если заполнено,

иначе

```
title
```

Для существующих страниц маршруты не менять.

Главная:

```
/
```

Услуги:

```
/services
```

Портфолио:

```
/portfolio
```

Блог:

```
/blog
```

Использовать `slug` только как идентификатор записи, а не как генератор маршрутов.

---

# Архитектурные требования

Обязательно соблюдать существующую архитектуру проекта:

* не выполнять запросы к БД из Blade;
* вся загрузка данных должна происходить в контроллерах или сервисах;
* использовать eager loading при необходимости;
* не дублировать код между контроллерами;
* использовать существующую модель `Page`.
